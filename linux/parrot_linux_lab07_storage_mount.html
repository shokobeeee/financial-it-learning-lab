📈 df と du — 「Filesystem使用量」と「Directory合計」は違う

50GSize
21GUsed
27GAvail
42%Use%
$ df -h / Filesystem Size Used Avail Use% Mounted on /dev/sda2 50G 21G 27G 42% / $ sudo du -shx / 20G / # 近い値だが、常に完全一致するとは限らない

削除済みFileをProcessがopenし続けると、Directoryからは消えて du が減っても、FilesystemのBlockはまだ使用中で df が減らないことがあります。

🔢 inode枯渇 — 容量が余っていても「No space left on device」

3.2MInodes
0.4MIUsed
12%IUse%
$ df -i / Filesystem Inodes IUsed IFree IUse% Mounted on /dev/sda2 3.2M 0.4M 2.8M 12% / # File/Directory 1個ごとにinodeを使う # 小File大量生成でBlock容量より先にinodeが尽きることがある

📝 /etc/fstab — 再起動後もmountする

SourceMountpointTypeOptions
$ cat /etc/fstab UUID=ROOT-UUID / ext4 defaults 0 1 # /data はまだ永続mount設定なし

編集したら即rebootではなく mount -a 等で先に検証するのが安全。fstab不備は起動トラブルにつながることがあります。

🗂 Filesystem — ext4 / XFS と fsckの考え方

ext4
Linuxで広く使われるFilesystem。journalあり。
XFS
大容量・並列I/Oなどでよく使われる。運用コマンドはext4と一部異なる。
Filesystem check
壊れた疑いがある場合は対象FS・状態に応じた適切な修復手順を取る。
$ dmesg -T | tail # Filesystem errorsが出ると、安全のためread-only化されるケースもある
重要: mount中のFilesystemに対して 何でもfsckすれば良いわけではない ↓ Filesystem種類 mount状態 バックアップ 復旧手順 業務影響 を確認 本番では安易な修復操作より まずログ・状態・手順確認

LVを大きくした ≠ Filesystemの容量が自動で必ず増えた Block Device側拡張 ↓ Filesystem側のgrow ↓ dfで確認 この「層が別」が重要
