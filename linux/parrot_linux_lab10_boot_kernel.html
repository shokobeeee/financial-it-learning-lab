🧭 Boot Stageを1つずつ理解する

1. FirmwareUEFI/BIOSがHardware初期化とBoot device選択Linux前
2. GRUBKernelとinitramfsを選び、Kernel parameterを渡す/boot
3. KernelCPU/Memory/Driver等を初期化vmlinuz
4. initramfsRoot FSをmountするための一時User spaceinitrd.img
5. Root FS本物の/を見つけてswitch_rootUUID/LVM等
6. systemdPID1としてUnit dependencyを解決PID 1
7. Target到達したい起動状態をまとめるmulti-user等
8. Servicesshd/nginx/Network等が起動Units

🐧 Kernel / initramfs — 更新後にBoot失敗したら？

KernelOS中核。Process/Memory/Driver等を管理。
initramfsRoot FSへ到達する前の一時環境。DriverやLVM等を含む。
Kernel cmdlineroot=、quiet、recovery等の起動Parameter。
$ uname -r 6.8.12-amd64 $ ls /boot vmlinuz-6.8.12 initrd.img-6.8.12 vmlinuz-6.7.9 initrd.img-6.7.9
Kernel update後にBoot失敗 ↓ GRUBのAdvanced options ↓ 旧KernelでBootできる？ ↓ できる → 新Kernel/initramfs/driver側を疑う 「OS全部壊れた」 とは限らない

📜 GRUB — どのKernelに何を渡して起動する？

menuentry 'Linux' { linux /boot/vmlinuz-6.8.12 root=UUID=ROOT-UUID ro quiet initrd /boot/initrd.img-6.8.12 }
GRUBまで出る？
GRUB menuが出る → Firmware/Boot deviceはかなり進んでいる Kernel選択後に止まる → Kernel / initramfs / root= 以降 GRUB自体が出ない → Bootloader / EFI / Disk / Firmware側も候補

🛟 Recovery — 壊れたときにどう入る？

GRUB → Advanced options → recovery / old kernel またはKernel cmdline: systemd.unit=rescue.target 起動後: mount -o remount,rw / vi /etc/fstab journalctl -xb
Recoveryで大事な考え
復旧手段は 「とりあえず再Install」 ではない まず: - どこまでBootしている？ - Root FSは見える？ - journalは読める？ - old kernelは起動する？ - bad configを戻せる？ - fstabを直せる？ 原因層に最短で入る
