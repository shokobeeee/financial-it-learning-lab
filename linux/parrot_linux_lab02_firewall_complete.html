DROP と REJECT の症状を比較

どちらも許可しませんが、クライアントからの見え方が違います。

ALLOW: HTTP/1.1 200 OK DROP: 返答を捨てる → timeoutのように見える REJECT: 拒否応答を返す → すぐ失敗が分かる
Rule Hit Counter — そのルールに本当に当たった？

HTTP / HTTPS / pingを実行すると、マッチしたルールのHitsが増えます。Hit=0なら別の場所で止まっている可能性も。

ルール順序と Shadowed Rule

上から最初に一致する学習モデル。上位の広いルールに隠された下位ルールには⚠を表示します。

例: 1. ALLOW TCP/80 Anywhere 2. DENY TCP/80 from 192.168.1.10 → 1番が先に一致するので2番は効かない → ↑ ↓ で順序を入れ替えて挙動を確認

🧠 Firewallでよくある勘違いを潰す

① 80番をALLOWすればWebは開く？
❌ nginxなどが80番でLISTENしていなければ開きません。
② pingが通ればWebも通る？
❌ pingはICMP。HTTPはTCP/80。別の通信です。
③ Firewall OFFなら安全に開通？
△ 通りやすくなるだけ。不要な通信まで通すので本番では雑にOFFにしません。

UFWとnftablesの関係
nftables
Linuxカーネルのパケットフィルタリングを管理する現行の仕組み。細かく制御できる。
UFW
Firewall操作を分かりやすくするフロントエンド。環境によっては未導入なので、この教材では「概念を学ぶ簡易操作」として使う。
重要
実機Linux Hostでは、まず sudo nft list ruleset や導入済みツールを確認してから操作する。
