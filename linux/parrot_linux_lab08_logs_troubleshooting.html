🔎 journalctlを絞り込む

(まだイベントなし)
Timelineをつなぐ

複数ログを「時刻」で並べると、原因→影響の順番が見えます。

🧪 grep / tail -f / wc — 大量ログを読む基本

$ grep " 500 " /var/log/nginx/access.log # 該当なし
巨大Logを全部catしない grep → 特定文字列 tail -n 100 → 直近だけ tail -f → 新着を追う wc -l → 件数 sort / uniq -c → 集計 awk → 列を扱う まず「絞る」

♻️ logrotate — Logを放置してDiskを埋めない

/var/log/nginx/*.log { daily rotate 14 compress missingok notifempty create 0640 www-data adm sharedscripts postrotate systemctl reload nginx endscript }

Rotationは「古いLogを別名にして新しいFileへ切り替える」運用。Applicationが新しいFileを再openできる仕組みも重要です。

ログ調査の基本: 1. 症状が起きた時刻 2. 影響範囲 3. 関係Service 4. journalctl -u / --since 5. Application固有Log 6. Kernel / auth / Disk 7. 複数Sourceを時系列で並べる 8. 原因と「結果として出たError」を区別 Error文字列だけ検索して終わらない
