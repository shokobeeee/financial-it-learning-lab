🔑 Password認証と公開鍵認証

公開鍵認証を作ってみる
💻 Client
秘密鍵
~/.ssh/id_ed25519
⇄
🐧 Server
公開鍵
~/.ssh/authorized_keys
まだ鍵ペアはありません。秘密鍵はクライアントから持ち出さず、公開鍵だけサーバーへ登録します。
何を保存する？
$ ls -la ~/.ssh (まだ鍵なし) # 秘密鍵: Clientが保持 # 公開鍵: Serverのauthorized_keysへ登録

公開鍵認証は秘密鍵をサーバーへ送る仕組みではありません。

🪪 Host Key / known_hosts — 接続先サーバーは本物？

初回接続
Host Keyが変わったら？
$ ssh learner@192.168.1.20 The authenticity of host '192.168.1.20' can't be established. Are you sure you want to continue connecting?

再構築で正当に変わる場合もあれば、別サーバーや中間者攻撃などの可能性もあるため、警告を雑に無視しません。

⚙ sshd_configを変更して安全に反映

設定
安全な反映手順
$ sudo sshd -t # 出力なし = 構文OK $ sudo systemctl reload ssh # 新しい接続で確認してから既存セッションを閉じる

既存セッションを残す → 構文テスト → reload → 新規接続テストで自分自身の締め出しを避けます。

🧩 コマンドを分解する

コマンドを押すと意味を分解します。
SSH一次切り分けの順
1. IPへ届く？ ping / route 2. SSH Portへ届く？ nc -vz host 22 ss -ltnp 3. sshdはactive？ systemctl status ssh 4. どの認証で落ちる？ ssh -vv 5. サーバーログは？ journalctl -u ssh 6. 鍵なら権限も確認
