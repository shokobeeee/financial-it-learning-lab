🧮 Subnet / CIDR — 同じネットワークか？

判断結果をrouteに翻訳

同一Subnetなら相手へ直接。別SubnetならDefault Gatewayへ渡します。

🚪 Routing / Default Gateway

Destinationviadev意味
$ ip route

Default Routeとは

「自分の知っているネットワークにない宛先は、このルータへ渡す」という最後の出口です。

192.168.1.10 │ ├─ 192.168.1.20 → 同じSubnet → 直接 │ └─ 8.8.8.8 → 別Subnet ↓ 192.168.1.1 Default Gateway

📣 ARP / Neighbor — IPからMACを知る

$ ip neigh (empty) # 同一LANでは「192.168.1.20はどのMAC？」をARPで問い合わせる

別Subnet宛てなら、ARPで探す相手は最終サーバーではなく次のHop＝Gatewayです。

📖 DNS / hosts — 名前をIPへ変える

server01.lab.testA192.168.1.20
db.localA192.168.1.30
www.demo.localCNAMEserver01.lab.test
$ getent hosts server01.lab.test 192.168.1.20 server01.lab.test

/etc/hosts の上書き

127.0.0.1 localhost # 192.168.1.99 server01.lab.test

getent hostsはOSが実際に使う名前解決を確認しやすい。digと結果が違うならhostsなどローカル要因も疑えます。

📦 DHCP — IPだけでなく4点セットを受け取る

DHCPでは通常、IPアドレスだけでなくPrefix、Default Gateway、DNSなども自動設定されます。

IP192.168.1.10
Prefix/24
Gateway192.168.1.1
DNS192.168.1.53
$ nmcli device show eth0 IP4.ADDRESS[1]: 192.168.1.10/24 IP4.GATEWAY: 192.168.1.1 IP4.DNS[1]: 192.168.1.53

🧩 コマンドを分解する

コマンドを押すと意味を分解します。

一次切り分けの型

1. ip addr 自分のIP / Prefixは正しい？ 2. ip route 同一Subnet？ Default Gatewayは？ 3. ping IP DNSを除外してIP疎通できる？ 4. getent hosts / dig 名前は正しいIPへ引ける？ 5. ip neigh LAN内のARP/Neighborは解決できる？
